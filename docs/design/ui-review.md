## 1. 事实与约束

### 1.1 三套分辨率，一张表说清

| 口径 | 尺寸 | 用途 | 截图换算 |
|---|---|---|---|
| **桌面 ADL 舞台** | **640×960** | 日常 UI/布局验收的**唯一口径**（`[main]` 窗口） | 客户区截图 1:1，1 图素 = 1 逻辑像素 |
| 桌面 150% 缩放假说 | 960×1440 | 高分屏误抓产物 | ÷1.5 |
| **真机逻辑** | **540×1206** | 手机上的 `stage.stageWidth/Height` | 手机截图 **1080×2412 ÷2** |
| 手机物理 | 1080×2412 | 用户截图原始件 | ÷2 |
| ~~480×854~~ | 禁用 | 历史踩坑口径，**不得用于验收** | — |

**坐标记账规则（全文遵守）**

1. 一律写**逻辑像素**（= AS3 里 `stage` 的像素），括号里注明来源；
2. 桌面图：`逻辑 = 截图坐标 × 640 / 图宽`（正常就是 1:1）；
3. 手机图：`逻辑 = 截图坐标 ÷ 2`；
4. **桌面 640 宽和真机 540 宽之间不能线性换算**：宽比 640/540 = 1.185，高比 960/1206 = 0.796，
   两个方向比例不同（2:3 vs 1:2.23），任何"按比例缩放看位置"的做法都是错的。
   → 真机布局只能用真机截图核对，桌面只保证 640×960 这一档。

### 1.2 为什么不能用 480×854 验布局

不是"偏一点"，而是**布局公式本身会算出不同结果**：

| # | 事实（代码位置） | 换成 480×854 的后果 |
|---|---|---|
| 1 | 大量**硬编码像素**：翻页箭头 `y = 700`、页码 `y = 720`、列表首行 `y = 90`（`BlacksmithListUI.as:100/118/140`、`BagListUI.as:144/162/183`、`ArtifactListUI.as:95/113/146`） | 舞台变矮到 854，700/720 原地不动，底部按钮按 `H-h-35` 上移 → 页码压按钮或留怪缝 |
| 2 | 宽度用 `stageWidth` 现算：`(stageWidth>>1)-w-40`、`(stageWidth>>2)*3-140`（`BlacksmithUI.as:92/101`、`HelpInfoUI.as:87/95`） | 480 宽时 `(480>>2)*3 = 360`，与 640 时的 480 完全不同，2×2 入口挤到左半屏 |
| 3 | 背景要拉伸：`_loc3_.width = stageWidth`（`HomeUI.as:79`、`IllustrationUI.as:51`） | 640 宽的底栏/背板被压扁，比例失真，"好看"的结论不可迁移 |
| 4 | 验收目标是 `[main]` 640×960（AGENTS.md §5），真机是 540×1206 | 480×854 两头都不是，**三方都不代表** |

**结论**：只用默认 `640×960`。要交叉验证真机口径，用 `-Width 540 -Height 1206`（窗口比 1080p 屏还高，属可选）。

## 4. UI 变更评审流程（强制）

任何**客户端 / UI / 布局**改动（含只改 `.as3` 补丁、只调坐标、只换图），都必须走完 5 步。
**没有走完 = 不允许合并**，即使 `pytest` 全绿。

```
① 预期画面（改之前写）
      ↓ 主 agent 抓 640×960 客户区截图
② 截图归档（命名规范见 §6）
      ↓ UI lane 逐条对照 §2 清单
③ 评审结论（通过 / 打回 + P0/P1 清单）
      ↓ 打回 → 回 ①（评审单追加"第 N 轮"）
④ 通过 → 主 agent 才允许 merge
      ↓
⑤ 合并后再抓一次同画面截图，确认与评审图一致
```

## 5. 新页面设计模板（线框级，只写结构，不写 AS3）

### 5.0 先纠正一个事实：铁匠铺**不是 tab**

代码事实（`BlacksmithUI.as:87-121`、`141-176`）：铁匠铺主页是 **2×2 四个入口**：

| 入口 | 图标 | 目标 | 门槛 |
|---|---|---|---|
| 打造 | `img_make` | `CITY_BLACKSMITH_LIST` + `data={ttype:1}` | FUN_20 |
| 附魔 | `img_enchant` | `CITY_BLACKSMITH_LIST` + `data={ttype:3}` | FUN_27 |
| 熔合 | `img_integration` | `CITY_BLACKSMITH_INTEGRATION_LIST` | FUN_35 |
| 神器 | `img_artifact` | `CITY_BLACKSMITH_ARTIFACT` | 无 |

- 上排 `y = H-h-260`、下排 `y = H-h-130`；左列 `x = (W>>2)-140-(w-290)`、右列 `x = (W>>2)*3-140-(w-278)`。
- 打造与附魔**共用同一个列表页**，只靠 `ttype` 区分 → 列表页标题必须显示当前模式，否则用户以为进错。

### 5.1 铁匠铺 · 列表页（打造 / 附魔 / 熔合 共用）

| 区域 | 坐标 | 内容 |
|---|---|---|
| A 顶栏 | `y=0..80` | 标题 30 号 `x=20,y=15`：「打造 · 武器」/「附魔 · 防具」/「熔合」；右上货币（金币 `x=W-220,y=6`、银币居中） |
| B 列表区 | `y=90..690` | 3 列网格：`x = 20 + col*(w+5)`、`y = 90 + row*(h+5)`；列宽 `w ≈ 196`（`(640-40-10)/3`），行高 `h ≤ 150`（4 行到 690，不压页码） |
| C 翻页条 | `y=700..750` | 上页 `x=(W>>1)-w-40`、下页 `x=(W>>1)+w+40`；页码 `x=(W-w)>>1, y=720`，格式 `1/3` |
| D 底栏 | `y=H-h-35` | 返回 `x=25`、主菜单 `x=W-w-25` |
| E 弹窗层 | 居中 | 详情/结果/确认，`x=(W-w)>>1, y=(H-h)>>1` |

**列表行结构（每格 196×150）**

```
┌──────────── 196 × 150 ────────────┐
│ [图标 88×88 居中, y=8]            │
│ 名称 30 号 居中 y=100              │
│ 需求 20 号 居中 y=124（2/5）       │
│ ┌ 状态角标 40×40 右上 ┐            │  可做 / 缺材料 / 已有
└───────────────────────────────────┘
```

- 可做：正常色；材料不足：整格 60% 透明 + 角标「缺材料」；已有：角标「已有」。
- 点击格子 → 详情（沿用 `MakeInfoUI`：左栏 300 宽文本 `x=30,y=100`，右栏 250 宽 `x=W-270,y=100`）。

**按钮**：主操作 `x=(W-w)>>1, y=H-h-130`（`MakeInfoUI.as:150-151`）；取消 `y=H-h-60`。
**禁用态**：材料不足时 `alpha=0.5` 且不响应，点击弹错误提示，不许静默。

**空态**：列表区居中 `y=390` 30 号「暂无可打造的装备」+ `y=430` 20 号「提升等级或收集图纸后再来」。

**错误提示位置**：业务错误（材料不足 `-1:xxx`）用**居中弹窗**（`TipItem`/`AlertUI`），不遮底栏；
网络/协议错误同位置，标题「提示」+ 一行正文 + X。本项目**没有**"顶部飘字"组件，不要设计它。
