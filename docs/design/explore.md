# 探险系统：数据还原与实现差距

按游戏策划视角，从 `exploreMap.txt` / `worldMap.txt` / `exploreEquip.txt` 反推原本的设计，
再对照当前服务端实现，列出差距。**所有规则以配置表为准，"本地设计"处会显式标注。**

## 一、配置表说了什么

`exploreMap.txt` 185 行，关键列：

| 列 | 含义 | 世界1 地图1 的实例 |
|---|---|---|
| `worldId` | 属于哪个世界（`worldMap.txt` 9 个世界） | 1 |
| `terrain` | 地形：1 平原 / 2 草地 / 3 雪地 / 4 沙漠 / 5 火山 | 1 |
| `star` | 评价分档 `1500:1000:700:500` | 同上 |
| `max_days` | 一次探险持续天数（**多数行是空的**） | 空 |
| `needExploreMap` | **前置地图**：必须先完成哪张 | 0（起点） |
| `needDiscoverRate` | 该图需要的**发现率** | 400 |
| `events` / `eventProbability` | 事件池与权重 `11:12:13:14:15` / `5700:2000:500:500:1300` | — |
| `catchPet` | 该图可捕捉的宠物 id（0 = 不可捕捉） | 0 |
| `passRewardPoint/Crystal/Goods` | 通关奖励 | — |
| `maxRewardPoint/...` | 单次收益上限 | — |

世界 1 的链条是严格线性的：
```
图1 (need 0, rate 400) → 图2 (need 1, rate 450) → 图3 (need 2, rate 500) → … → 图10
   → 图11 (need 212, terrain 2, rate 1500)   ← 换地形，明显是"世界1 的下一区域"
   → 图12 (need 11, catchPet 6002)           ← 开始能抓宠
```

**所以"只有一张地图能进"不是 bug，是设计**：起点图中只有 `needExploreMap == 0` 的那张开放，
后续必须靠**发现率**逐张解锁。

## 二、原本的玩法循环

1. 进世界 → 看到该世界的地图链
2. 选一张已解锁的地图 → **派队伍出发**（消耗探险体力 `explore_ap`）
3. 队伍在图上推进，跑**发现率**（`needDiscoverRate` 是这张图的通关线）
4. 过程中按权重随机事件：战斗（57%）、采集、遭遇、宝箱、稀有事件
5. 收益：道具/水晶/银币（受 `maxReward*` 限制）、宠物经验、**可捕捉宠物**（`catchPet`）
6. 发现率达标 → 这张图通关 → **下一张图解锁**；世界最后一张通关 → 下一个世界

坐骑（`exploreEquip` type 1）与探险装备（type 2/3）是**派遣加成**：
坐骑影响行进速度/耗时，装备影响队伍强度与收益。

## 三、当前实现的差距（按严重度）

| # | 差距 | 后果 |
|---|---|---|
| 1 | **发现率不落地**：`now_discover_rate` / `add_discover_rate` 恒为 0，没有持久化 | 永远打不满 `needDiscoverRate` → **永远解锁不了第二张图** → 玩家只看到一张能玩 |
| 2 | **一次性结算**：103 一按就返回结果（`is_finish:1`），没有"出发中/倒计时/收获" | 没有挂机派遣的节奏，点一次就没下文 |
| 3 | **地图列表不带解锁态** | 客户端无法把未解锁的图灰掉（它自己把 `isClick` 硬编码为 true） |
| 4 | **没有派遣队伍概念** | 不选宠、不选坐骑，`energy`/`supply` 都是编的 |
| 5 | 事件恒为战斗 | 探险事件池 5 种只用了 1 种 |

## 四、本轮实现（只做第 1 项）

理由：它是"只有一张图"的直接原因，且不需要客户端改包。

- 新表 `explore_progress(player_id, gid, discover_rate, cleared_at)`
- `103` 胜利后按 `LOCAL DEFAULT` 增加发现率（每场 +100），返回真实的
  `now_discover_rate` / `add_discover_rate` / `need_discover_rate`
- `98` 的每行补 `discover_rate` / `need_discover_rate` / `is_open`：
  `needExploreMap == 0` 或前置图 `discover_rate >= 其 needDiscoverRate` 即开放
- 未解锁的地图调用 `103` 时返回 `-1:100`（客户端会弹提示，而不是静默白跑）

**未做（需客户端改包）**：派遣倒计时、队伍编成、事件多样化、列表灰显。

# 探险重做（2026-10-23 晚，按反馈重设）

## 一、一张地图 = 三场连续战斗

原来的实现是"一次探险 = 一场战斗 = 直接清图"，观感和节奏都不对。改为：

- 每张地图有 **3 场战斗**（同一张图连续推进，不重置地图）
- 每场战斗消耗 **1 点探险体力**（`explore_ap`）
- **连胜 3 场才算通关**；中途任一场失败 → 该图进度归零，血量恢复满，重新打
- 通关才弹"通关奖励"，且**每张图只给一次**

## 二、血条：每场重置（不做跨场继承）

拆包确认客户端没有任何"跨场血量"字段（`ExplorePveUI` 每场只吃一份 `battle_result`），
原始设计就是**每场满血开局**。所以不做继承——客户端没有承载它的入口，
硬做只能靠我们改写 `att_list` 的 hp，属于额外发挥，已放弃（用户确认）。

保留的血量相关逻辑：只有 `max_star_reward` 的"满星"判定，暂时也按"通关即满星"处理。

## 三、星级奖励（重新设计）

`exploreMap.txt` 的 `star` 列是 `1500:1000:700:500`——**四个数值，是星级奖励额度**。
按通关时的剩余血量百分比评星：

| 星级 | 条件（剩余血量） | 奖励点数 |
|---|---|---|
| ★★★★★ | ≥ 90% | 1500 |
| ★★★★ | ≥ 70% | 1000 |
| ★★★ | ≥ 50% | 700 |
| ★★ | ≥ 30% | 500 |
| ★ | 通关 | 250（`LOCAL DEFAULT`，表里只有 4 档） |

**每档只能领一次**：记录 `star_best`，只在"本次星级 > 历史最佳"时发放差额，
所以刷图不会无脑产出，但打得更漂亮能再领一次更高档。

## 四、后期地形怎么解锁（第二问）

配置表里地形是**沿全局链自然推进**的，不需要额外的解锁条件：

| 地形 | 首次出现在链中位置 |
|---|---|
| 平原 | 第 1 关 |
| 草地 | 第 23 关 |
| 雪地 | 第 45 关 |
| 火山 | 第 68 关 |
| 沙漠 | 第 92 关 |

解锁完全由 `needExploreMap` 决定：打完前一关（3 场胜利）下一关自动开放。
所以"雪地/沙漠怎么解锁"的答案是——**顺着链打通草地/雪地/火山段就到了**，
不需要单独的门票或道具。

补充设计（未实现，建议）：
- **地形决定敌人类型**：雪地出冰系、沙漠出岩系（`monster.txt` 里有对应物种，可按地形筛选）
- **地形决定难度系数**：越靠后的地形，`reference_lv` 更高
- 客户端世界地图（`WorldMapUI`）目前点不动，所以链是本阶段唯一入口

## 五、实现状态

- 已改：3 场战斗 / 血条继承 / 通关奖励一次性 / 星级奖励一次性
- 待做：地形影响敌人类型与难度、世界地图入口

# 客户端改包记录（2026-10-23 晚）

## 已改 1：未解锁地图显示锁

`ExploreMapListUI.as` 里 `"isClick":true` 两处 → `"isClick":_loc5_.is_open != 0`。
服务端下发 `is_open` 后，锁住的图会画 `clip_lock` 并拒绝进入。

## 已改 2：探险背景音乐重叠

**根因**：`ExploreMapListUI.as` 用 `SoundManager.play("sound_event_2xx", 2147483647)`
无限循环播放地图 BGM，而切换界面时只 `stop("sound_back")`，上一首会残留并与新音乐叠加。

**改法**：播放地图 BGM 前先 `SoundManager.stopAll()`，保证同一时刻只有一首背景音乐。

**打包链路**（可复用）：
```
ffdec -export script <dir> <in.swf>
（只改需要的 .as，单独丢进一个只含该文件的目录）
ffdec -importScript <in.swf> <out.swf> <（只含改动文件的目录）>
adt -package -target apk-captive-runtime -storetype pkcs12 -keystore build/remote.p12 ...
adb install -r
```
注意：`-importScript` 是全量编译，**不能导入全部脚本**——`Navigator.as` 含反编译出的
`goto`，FFDec 编译器不支持会直接失败；只导入改动文件才成功。

# 探险事件还原（2026-10-24）

## 一、事件类型

`exploreMap.txt` 的 `events` 是 `地图id*10+类型`，末位即类型；`eventProbability` 是
同名权重。表里只出现 1-7，但客户端为 **1-13** 各备了一套文案/背景/音效，而
`exploreEquip.txt` 的 `effectType` 又按 6-13 成组提供"伤害免疫"装备
（`4000` = 40.00%，`2000` = 20.00%），`help.txt:19` 也写明"要根据地图的地形和灾害
来租赁坐骑和装备"——所以不同地区会遇到不同灾害。

| 类型 | 文案（ui.txt） | 背景（map.swf） | 处理 |
|---|---|---|---|
| 1 | —（进战斗页） | — | 战斗 |
| 2 | 382 发现了城镇 | `map_event_2<world>` | 休整 |
| 3 | 383 发现了温泉 | `map_event_3` | 休整 |
| 4 | **没有文案** | `map_event_4`（宴席） | 休整（原实现误当灾难） |
| 5 | 384 发现了绿洲 | `map_event_5` | 休整 |
| 6 | 385 暴雨 | `map_event_6` | 灾难 |
| 7 | 386 洪水 | `map_event_7` | 灾难 |
| 8-13 | 387-392 火山/暴风雪/沙尘暴/龙卷风/台风/疾病 | 同名背景 | 灾难 |

配置表没有存"哪个地区对应哪种灾害"，服务端按地区主题与装备备注推断，作为
**LOCAL DEFAULT**（`LOCAL_EXPLORE_DISASTERS_BY_WORLD`）：

| 世界 | 主灾害（events 的 6 号槽） | 次灾害（7 号槽） |
|---|---|---|
| 1 樱花之岛 | 6 暴雨 | 12 台风 |
| 2 神龙之国 | 7 洪水 | 6 暴雨 |
| 3 神圣之国 | 8 火山 | 6 暴雨 |
| 4 沙丘之国 | 10 沙尘暴 | 13 疾病 |
| 5 狂野之国 | 11 龙卷风 | 13 疾病 |
| 6 棕榈群岛 | 12 台风 | 7 洪水 |
| 7 星辰之国 | 11 龙卷风 | 6 暴雨 |
| 8 神鹰之国 | 13 疾病 | 8 火山 |
| 9 冰川大陆 | 9 暴风雪 | 13 疾病 |

只有 6 号槽的地图不会出现次灾害；未知地区回落到 6/7。

## 二、行程资源（LOCAL DESIGN）

客户端 HUD 显示 体力（`img_icon_25`）/补给（`img_icon_22`）/天数（`img_icon_23`）/
发现率（`img_icon_14`），结算面板显示 `cost_*` / `add_*` 增量。

- 基础 体力/补给 各 1000；装备 `effectType` 1/2 分别加体力/补给（+400 / +200）。
- 每场战斗 −100 体力、−50 补给；休整 +200 / +200（封顶）；灾难 −300 / −300。
- 灾害伤害按匹配免疫装备的百分比减免（多件相加，最多 100%）。
- 每次事件 +1 天；行程从第 1 天开始。体力或补给 ≤0 → `is_tired=1`（客户端换成
  疲惫坐骑 `m<horse>_2` 与 `sound_event_200`）。
- 发现率 = 基础值（`needDiscoverRate/3`）+ 坐骑按地形的加成 + 装备
  `effectType=3`；休整只给一半。所以租对坐骑/装备能少跑一趟、拿更高星级。
- 行程结束（该图打通）后三列清零，下次按当时装备重新初始化。

## 三、好运 / 厄运

`ExplorePveUI.as:228` 与 `ExploreEventResultUI.as:209` 只在 `surprise_rate>1` 时画
"好运降临，本次探险的奖励加倍" / "厄运降临，本次探险的惩罚加倍" + `clip_num_3`。
精英遭遇本来就是奖励 ×2，现在同时回 `surprise_rate=2`，战斗结算页会显示好运横幅。

## 四、通关 / 满星 / 星级

- **通关奖励**：发现率打满的那次发一次；`finish_reward` 里的道具/装备/宠物/图鉴
  真的入账。
- **满星奖励**：评价到 5 星时发一次；`max_star_reward` 的点券/水晶/商品现在也真的
  入账（原来只画在面板上，玩家拿不到）。
- **星级按天数**（`help.txt:19`「完成探险用的时间越少，评价就越高」）：≤5 天 5 星、
  ≤8 天 4 星、≤11 天 3 星、≤15 天 2 星，否则 1 星。三场战斗通关正好 4 天；多一次
  休整/灾难仍在 5 星线内，两次以上才掉到 4 星（57% 战斗 / 43% 休整的事件池下，零休整
  只有约 18% 概率，太苛刻）。
- 结算面板需要的 `cur_star` / `is_finish_reward` / `is_max_star_reward` 现在都会下发，
  否则 `ExploreResultItem.showFinish()` 永远画"本次探险没有获得奖励"。

## 五、关卡门禁 / 完美通关 / 列表（2026-10-24 晚）

- **解锁**：前置图的发现率达到其 `needDiscoverRate`（通关）后，下一张图才 `is_open=1`；
  未解锁的图在客户端显示锁，服务端的 99（详情）和 103（出发）也会拒绝（`-1:100`）。
- **完美通关**：一次 5 星通关把该图 `star_best=5`，之后 `is_perfect=1`：
  客户端把格子锁住、99/103 都拒绝——即"这关关闭了"。4 星通关只解锁下一关、
  **不关闭**本关，可以回去补 5 星。
- **列表起点**：98 从"第一张还没通关的图"往前留 4 张开始（`LOCAL_EXPLORE_LIST_LOOKBACK`），
  这样刚打完的 4 星图还在第一页、能点回去补星；已完美通关的图只在窗口内以锁住的样子出现。
- **星级显示**：98 每行新增 `best_star` / `is_perfect` / `is_cleared`；改包后的
  `ExploreMapListUI` 把 `best_star` 写进格子的 `star` 字段（`GameUtil.getStar` 画星），
  并用 `is_open != 0 && !is_perfect` 决定是否可点。

## 六、后半程怪物多样化

旧实现把 `base_id=1`（原味波利 lv1）写死进每一张探险图，而 monster.txt 在 20~30 级
又没有怪，所以后面几十张图都只有一只 lv1 波利。现在：

- **物种**按这张图在**全局链**上的位置选（`LOCAL_EXPLORE_SPECIES_STEP=5` 每关 +5），
  从 `monster.txt` 里挑 ±80 级窗口内、且符合地形 `properties` 的怪；
- **出场等级/数值**统一用 `reference_lv`（= min(关卡参考等级, 队伍等级 + 15)），
  显示等级与 `_monster_stats` 用同一套数，换皮不会把难度带崩；
- 同一张图按当前发现率轮换对手（连打三场不会永远同一组），领队由 gid 决定；
- 关卡参考等级也改成**全局链位置**递增（跨世界不重置），后半程不会又回到 lv10。

## 七、已知限制

- **4 号大餐没有文案**：`GameUtil.getExploreEvent` 没有 `case 4`，只能显示宴席背景；
  要补文案必须改客户端（`ui.txt`/AS3），服务端无法补。
- 灾害对应表、资源数值、星级阈值都是 LOCAL DEFAULT，集中在 `app.py` 顶部常量
  （`LOCAL_EXPLORE_*`）里，可按手感调整。
- 未知事件类型（0 等）按"什么都不发生的一天"处理：只 +1 天，不扣资源。
