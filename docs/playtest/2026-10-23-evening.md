## D-13 背包里仍有灰掉的道具；人物的"使用道具"里出现宠物道具

**现象**：家园→使用道具 出现只能给宠物用的道具；宠物界面出现只给人用的道具；还有灰色（不可点）道具。

**根因（证据）**
1. `PropItem.as:328-333`：`data.on == 0` 才禁用格子。服务端 22 号响应**从不发 `on`**，
   所以所有道具都显示成可点，点了才回 `-1:100`。
2. `22` 请求只有 `ttype/p/n`，**没有上下文参数**（是"人物在用"还是"宠物在用"）。
   人物/宠物的区别只在**后续 50 号命令的 `target`**（服务端已按 `useType` 校验：
   `target<=0` + 宠物道具 → `-1:506`）。所以服务端**无法**按界面把道具灰掉。

**已修部分**：22 号补 `on` 字段，仅对 `prop.txt type=0`（真正的非效果道具，如 10506 王国勋章）
置 0。当前道具页 79 可用 / 1 禁用。
第一版按"没有效果规则"判定，误伤了 14 个真有用途的道具（`10027 狩猎秘籍` 的 `value` 是小数
`1.5`；`10013 扩建证书`/`10028 遗忘之锤`/`10035 推磨钱袋` 的 `value=0` 但有固定语义），已收窄。

**未修部分**：按 `useType` 在界面上过滤/灰显 —— **必须改客户端**（`BagListUI`），
服务端没有上下文可依据。

**状态**：部分修复；上下文过滤 → 未修（待改包）。

## D-14 图鉴"没有对齐居中"

**现象**：获得图鉴弹窗的文字/图片看着没对齐。

**证据**（对用户提供的截图做像素测量，1080×2412）
| 元素 | 实测中心 x |
|---|---|
| 弹窗面板边框 | 536 |
| 宠物图片（粉色团子区域） | 537 |
| 【获得图鉴】 | ≈552 |
| 【原味波利】 | ≈528 |
| 【图鉴奖励】 | ≈552 |
| 屏幕中心 | 540 |

误差 4~12px。代码侧 `GetPicItem.as:182` 与 `:260` 的写法
`x = this.width - child.width >> 1` 在 AS3 里等价于 `(width - child) / 2`（`-` 优先于 `>>`），
算法正确。

**结论**：按测量是居中的。若观感仍偏，可能指的是另一个界面
（`IllustrationTaskUI`，图鉴里程碑页，其文字坐标是硬编码 `x = 20 / 120`，确实左对齐）。

**状态**：未定位（需要用户指明是哪个界面 / 圈出元素）。

**验证**：`98 ttype=1` 返回 `{"type":2,"world":1,"list":[...]}`，冒烟通过。

**状态**：已修（回退恢复可用）；世界选择 → 未修（待客户端改包）。

## D-17 狩猎不能切换宠物

**现象**：点两侧宠物无法更换。

**根因（证据，两个叠加）**
1. `HunterTaskUI.as:287-310`：点**有宠物**的格子发 `45`，且 `ttype` **写死为 1**；点**空格子**
   才 `flow(FIGHT_PET_LIST)` → `42` → 选中发 `44`（`FightPetListUI.as:148-164`，`ttype` 仍是页面类型 1）。
   **`ttype` 是页面类型，不是槽位**，我上一版把它当槽位用，两次选择都写进槽 1、互相覆盖。
2. `5` 号在未安排出战时会**用普通宠物填充两个格子**，客户端于是认为格子已占用，
   点击走"下场"分支（`45`），而服务端清的是本来就为 0 的槽位 → 毫无变化。

**修复**
- `44`：填**第一个空槽**（1 再 2），不再读 `ttype` 当槽位。
- `45`：把该宠从出战队伍移除（`squad_slot=0`）。
- `5`：**只返回真正安排的出战宠物**（按 `squad_slot` 排序），空槽让客户端画占位、可点开选宠。

**验证**：线上 `5` 返回 `pets: []`（未安排时）；单测覆盖"44 两次 → 槽 1/槽 2 不同宠 →
45 下场 → 再 44 补位"。

**状态**：已修（待真机确认）。
