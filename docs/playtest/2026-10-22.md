## D-01 家园角色图片男女图层重合

- **现象**：家园角色立绘上男女图层叠在一起。
- **复现**：进入家园，观察右侧角色立绘。
- **证据**：`[已证实]` 服务端 `_base_skin_layers` 的键位与注册值不一致。
- **根因（已证实部分）**：`LOCAL_BASE_SKIN_LAYERS` 原本用 `1: 男 / 2: 女` 做键，
  但 `/regplayer` 只接受 `sex ∈ {0,1}`，且 `sex != 1` 时存女性三元组（`app.py:863`）。
  于是 `_base_skin_layers(0)` 落到男性默认值 —— **女性玩家被画成男性**。
- **修复**：键位改为 `1: 男 / 0: 女`，并对非法值回退到男性。
- **回归**：`test_skin_string_carries_the_head_and_hair_layers` 增加断言
  「女性玩偶里不得混入男性头/发图层（100002/100003）」。
- **仍待确认**：`ShowItem.as:62-80` 只按 `z` 排序后逐个 `addChild`，**不做图层替换**。
  `skin.txt` 里基础层与装备图共用 z（身体 z=6、头发 z=5、头 z=4），
  装备图 `100010`(z=6) / `101030`(z=5) / `100040`(z=4) 与基础层完全同 z。
  若这些装备图是整身立绘，就会与身体叠加成「两个人物」。
  需要用能看图的模型比对一次家园立绘，再决定是否要「同 z 覆盖」。

## D-02 / D-05 / D-07 列表格子无图标（装备 / 素材 / 宠物道具）

- **现象**：背包各分页的格子全都没有图案，点进详情页才有。
- **复现**：家园 → 装备 / 素材 / 道具，观察 3×3 格子。
- **证据**：`[已证实]` 客户端 `PropItem.as:233`。
- **根因**：`PropItem.as:233` 是 `getDefinition("p" + data.icon)` —— **客户端自己拼 `p` 前缀**。
  服务端 `22` 号却返回了已经拼好的 `"p10007"`，客户端于是查 `"pp10007"`，
  `getDefinition` 返回 `null`，`new null()` 抛异常，被 `PropItem.as:243` 的**空 catch 吞掉**。
  结果就是格子永远没图，且没有任何报错痕迹。
  详情页 `39` 返回的是裸数字，所以点开才有图 —— 这正好解释「点击才看到」。
- **契约规则（本次固化）**：

  | 消费者 | 取图标方式 | 服务端必须返回 |
  |---|---|---|
  | `PropItem.as:233`（背包格子） | `getDefinition("p" + icon)` | **数字** `10007` |
  | `EquipInfoUI.as:197`（装备详情） | `getDefinition("p" + icon)` | **数字** |
  | `GetPicItem.as:170`（奖励图标） | `getDefinition("p" + icon)` | **数字** |
  | `IconItem.as:79` | `getDefinition("" + icon)` | **完整类名** `p10007` / `img_silver_0` |

- **修复**：`22` 号改为返回数字。
- **资源核对**：`p10007`/`p11001` 在 `prop.swf`，`p20001` 在 `skin.swf`，符号均存在。
- **回归**：`test_new_character_gets_the_local_starter_equipment_in_the_bag`、
  `test_shop_buy_deducts_currency_and_stacks_inventory`、
  `test_seed_items_bag_list_renders_every_team` 断言改为「必须是 int」。
