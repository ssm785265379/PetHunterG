## D-01 家园角色图片男女图层重合

- **现象**：家园角色立绘上男女图层叠在一起。
- **复现**：进入家园，观察右侧角色立绘。
- **证据**：`[已证实]` 服务端 `_base_skin_layers` 的键位与注册值不一致。
- **根因（已证实部分）**：`LOCAL_BASE_SKIN_LAYERS` 原本用 `1: 男 / 2: 女` 做键，
  但 `/regplayer` 只接受 `sex ∈ {0,1}`，且 `sex != 1` 时存女性三元组（`app.py:863`）。
  于是 `_base_skin_layers(0)` 落到男性默认值 —— **女性玩家被画成男性**。
- **修复**：键位改为 `1: 男 / 0: 女`，并对非法值回退到男性。
- **回归**：`test_skin_string_carries_the_head_and_hair_layers` 增加断言
  「女性玩偶里不得混入男性头/发图层（100002/100003）」。
- **仍待确认**：`ShowItem.as:62-80` 只按 `z` 排序后逐个 `addChild`，**不做图层替换**。
  `skin.txt` 里基础层与装备图共用 z（身体 z=6、头发 z=5、头 z=4），
  装备图 `100010`(z=6) / `101030`(z=5) / `100040`(z=4) 与基础层完全同 z。
  若这些装备图是整身立绘，就会与身体叠加成「两个人物」。
  需要用能看图的模型比对一次家园立绘，再决定是否要「同 z 覆盖」。

## D-02 / D-05 / D-07 列表格子无图标（装备 / 素材 / 宠物道具）

- **现象**：背包各分页的格子全都没有图案，点进详情页才有。
- **复现**：家园 → 装备 / 素材 / 道具，观察 3×3 格子。
- **证据**：`[已证实]` 客户端 `PropItem.as:233`。
- **根因**：`PropItem.as:233` 是 `getDefinition("p" + data.icon)` —— **客户端自己拼 `p` 前缀**。
  服务端 `22` 号却返回了已经拼好的 `"p10007"`，客户端于是查 `"pp10007"`，
  `getDefinition` 返回 `null`，`new null()` 抛异常，被 `PropItem.as:243` 的**空 catch 吞掉**。
  结果就是格子永远没图，且没有任何报错痕迹。
  详情页 `39` 返回的是裸数字，所以点开才有图 —— 这正好解释「点击才看到」。
- **契约规则（本次固化）**：

  | 消费者 | 取图标方式 | 服务端必须返回 |
  |---|---|---|
  | `PropItem.as:233`（背包格子） | `getDefinition("p" + icon)` | **数字** `10007` |
  | `EquipInfoUI.as:197`（装备详情） | `getDefinition("p" + icon)` | **数字** |
  | `GetPicItem.as:170`（奖励图标） | `getDefinition("p" + icon)` | **数字** |
  | `IconItem.as:79` | `getDefinition("" + icon)` | **完整类名** `p10007` / `img_silver_0` |

- **修复**：`22` 号改为返回数字。
- **资源核对**：`p10007`/`p11001` 在 `prop.swf`，`p20001` 在 `skin.swf`，符号均存在。
- **接口实测**（修复后直接请求 `showId=22`）：

  ```
  ttype=1 道具  icon=10001,10002,10003   (int)
  ttype=2 素材  icon=11001,11002,11003   (int)
  ttype=3 装备  icon=20001,20002,20003   (int)
  ```

- **回归**：`test_new_character_gets_the_local_starter_equipment_in_the_bag`、
  `test_shop_buy_deducts_currency_and_stacks_inventory`、
  `test_seed_items_bag_list_renders_every_team` 断言改为「必须是 int」。
- **仍待**：真机目视确认（本次执行窗口的模型不支持读图，改用接口+符号存在性证据；
  下次需用看图模型复验三个分页的格子图案）。

# 第二轮：根因定位与修复状态（2026-10-22 晚）

本轮用「主任务调度 + 并行只读侦察 + 串行落地」的方式复查了全部 12 条缺陷。

## 已修复并在单测中锁死

### D-01 男女图层重合 —— 不是"叠加算法"问题，是性别串层
- **根因**：男号（`players.sex=1`）身上实际穿着**女装** `20005`（`equip.txt` 里 `sex=0`）。
  `equip.txt` 每件装备男女各一行、`imageId` 不同（20002 男→100020，20005 女→100040），
  而 `_role_skin_string()` 只取 `imageId`、**从不比对 `equip.sex`**，于是男性基础三层
  与女性铠甲图被一起 `addChild`。
- **佐证**：`ShowItem` 全类没有任何替换/互斥逻辑，有多少 id 叠多少；`skin.txt` 里基础层与
  装备图共用 z 值（6/5/4），所以"按 z 覆盖"不成立（铠甲 z=4 与**头** z=4 同层）。
- **修复**：加性别闸门；跨性别装备自动映射到同 `(name,type)` 的另一性别行，避免"过滤后
  装备消失"。顺带修正 `LOCAL_BASE_SKIN_LAYERS` 键位（原 1/2 与注册值 0/1 不匹配，
  导致女性玩家被画成男性）。

### D-03 装备后模型消失 + 属性 undefined —— 37 号冒充玩家数据
- **根因**：`EquipInfoUI` 发完 37 立刻 `flow(GAME_HOME)` 且**不再拉 showId=2**；
  `MainUI.as:317` 的 `default` 分支把未匹配命令的响应体直接交给当前界面的 `readDatas`，
  而 `HomeUI.readDatas` **不判断命令号**。旧实现回 `{"value":"ok"}`，
  于是 `GameUtil.skin = undefined` → `ShowItem.removeAll()` **立绘被清空**，
  所有文本行打印 `undefined`。
- **修复**：37 改为返回与 2 号同形的完整载荷（保留 `value:"ok"`）。无需重打包客户端。
- **顺带**：`sortOn("z",16)` 中的 16 是 `Array.NUMERIC`（升序），不是 DESCENDING —— 旧注释写错了，已更正。

### D-02 / D-05 / D-07 列表格子无图标 —— 一个前缀写反了
- **根因**：`PropItem.as:233` 是 `getDefinition("p" + data.icon)`，**客户端自己拼 p**。
  服务端 22 号返回了已拼好的 `"p10007"` → 查 `"pp10007"` → `null` → `new null()` 抛错 →
  被 `PropItem.as:243` 的**空 catch 吞掉** → 格子永远空白且无任何日志。
  详情页 39 返回裸数字，所以"点开才有图"。
- **契约（本项目固化）**：`PropItem`/`EquipInfoUI`/`GetPicItem` = 数字；
  `IconItem`/`ImgItem` = 完整类名。目前**没有任何服务端字段走后者**。
- **修复**：22 号返回数字。接口实测三个分页均为 int。
- **顺带补漏**：26（图鉴详情）与 114（属性转移）缺 `icon` 字段 —— 前者导致图鉴详情
  **永远没有立绘**（异常被 catch），后者导致转移确认框没有宠物图。

### D-06 宠物道具不生效 —— 不是"没累加"，是守卫把行挡住了
- **根因**：`seed_items.py` 把每行的 `item_type` 硬编码成 `0`，而使用守卫是
  `catalog_type != row.item_type → -1:100`。于是 13 种经验道具里绝大多数一点就失败、
  且不扣道具（看起来像"用了没反应"）。另：响应缺 `type`，客户端选不出结果弹窗，用完零反馈。
  本地目录还把 10011 记成 1,000,000（prop.txt 真值 10,000，差 100 倍）。
- **修复**：效果规则改为**直接读 prop.txt**（`type`/`value`/`useType`），不再依赖 13 项白名单；
  启动时按 prop.txt 回填存量行的 `item_type`/`use_type`；使用时懒自愈；补 `type` 回显；
  扣数量加 `quantity > 0` 守卫防连点重复结算。

### D-12「抓到的宠物属性全一样」
- **根因**：全属性面板（13 号）用 `LOCAL_PET_BASE_STATS`，只写死 1001/2019 两只，
  **其它物种一律回退成 1001 火龙**（39/65/52/60/43/50）。pet.txt 本来就有每物种真值
  （5001 原味波利 = 99/90/115/90/78/95）。
- **修复**：改读 `pet.txt`；`hp_tp..mag_def_tp` 由恒 0 改为真实 `pro_*`（"强化值"不再永远 0）；
  `gw_rate` 按该宠物 `grows` 区间归一（高星下限 10/20/40 必须扣除，否则出生就是"中超"）。
