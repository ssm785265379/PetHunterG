# 宠物列表与详情协议分析

本文依据临时导出的 AS3 客户端静态追踪，描述 UI 发出的请求和实际读取字段。它不是旧服务器抓包，也不能证明字段是否可空、服务端计算规则或所有响应字段类型。临时导出路径为 `C:\Users\ssm\AppData\Local\Temp\pethunter-all-scripts\scripts`。

## 请求与路由

`CommandManager.as:46-50,279-340,343-430` 定义宠物列表为命令 11、详情为命令 12。普通请求由 CommandManager 映射到 `m=show&showId=<命令号>`，参数进入表单请求；`APetHunter.as:133-162` 将响应中的命令号与 JSON 分发给当前 UI。

| 操作 | 请求参数 | 证据 |
|---|---|---|
| 列表 | `p`：当前页，从 1 开始；`n`：每页 9 | `PetListUI.as:79-95,157-163` |
| 详情 | `index`：列表行中宠物索引 | `PetListUI.as:165-175`; `PetInfoUI.as:667-670` |

列表每页固定创建 9 个格子；下一页硬限制为 `_page < 9`，上一页仅要求 `_page > 1`。响应中的 `max_pet_num` 决定格子开/锁状态及 `_maxpage` 显示相关内部状态，但 UI 没有用它限制翻页。分页公式为 `max_pet_num / 9 + 1 | 0`（`PetListUI.as:213-220`），存在恰好整页时多一页的可能；不要把此公式误当成服务器分页规则。

## 列表响应消费

`PetListUI.as:201-263` 读取：

| 字段 | 客户端用途 / 推断类型 |
|---|---|
| `pet_num` | `int(...)` 转换；未用于格子数量，确切语义未明 |
| `max_pet_num` | `int(...)` 转换；容量上限，用于开槽显示 |
| `add_pet_card_num` | 与 `own_card_num` 比较并显示扩容卡需求；数值 |
| `own_card_num` | 与扩容卡需求比较；数值 |
| `pets` | 必须是可取 `length` 且可按下标访问的数组；当前页记录 |
| `pets[].index` | 传给详情命令 12；数值/标识，具体类型未由 AS3 限定 |
| `pets[].id` | 查 `pet` 配置名称；数值或可转字符串的 ID |
| `pets[].icon` | 传给 `PetItem` 作图标资源选择；字符串/资源 ID |
| `pets[].name` | 可选自定义名；缺省时回退配置名 |
| `pets[].lv` | 显示等级；数值 |
| `pets[].battle_state` | 显示战斗状态；枚举/布尔编码未确认 |

空槽规则完全在客户端：全局槽序号小于容量上限时显示可用空位；恰好等于容量上限的第一个空位显示为“可扩容”锁槽；后续槽关闭（`PetListUI.as:221-258`）。点击扩容槽显示 `p10013`，拥有卡数达到需求时弹确认框；确认会发命令 40 `ADD_PET_COUNT_KEY`，不带参数，然后请求列表刷新（`PetListUI.as:177-198,208-212,265-270`; `CommandManager.as:104`）。此变更不属于 11/12 的最小只读范围。

## 详情响应消费

命令 12 的响应由 `PetInfoUI.as:275-379,380-528` 使用。基础字段：

| 字段 | 客户端用途 / 类型 |
|---|---|
| `index` | 保存到页面数据并供锁定、改名、进化、放生等操作回传；标识 |
| `star` | 显示星级并决定锁定提示分支；数值 |
| `is_lockable` | 条件判断，决定是否创建锁定按钮；布尔/真值 |
| `is_locked` | 控制锁图层与按钮方向；布尔/真值 |
| `icon` | 解析为 SWF 资源 `p<icon>` 并绘制；资源 ID |
| `id` | 缺少 `name` 时查询 `pet` 配置；宠物配置 ID |
| `name` | 可选自定义名；字符串 |
| `lv` | 显示等级并与进化目标 `need_lv` 比较；数值 |
| `pro` | 传给 `GameUtil.getFive(int(...))` 显示属性值；数值 |
| `pic` | 若存在，调用 `GameUtil.getPic` 加载；资源 ID |

`free_goods_id` 与 `free_goods_num` 可选：放生确认提示与放生结果使用它们；代码对数量经过数值格式化，对 ID 经 `prop`/`pic` 配置查图标（`PetInfoUI.as:277-294,380-384,555-583`）。

`next_pet` 可选；若为空显示无后续进化文案。存在时客户端读取 `id,need_lv,need_money,need_point,need_crystal,need_goods[]`；材料数组行读取 `id,num`。这些字段仅用于展示目标和条件图标，实际是否可进化、扣费及进化状态变更不由此响应可推知（`PetInfoUI.as:385-505`）。

## 本地配置依赖

`client/air51-repack/src/data/zh-CN/config/pet.txt:1-8` 的表头包含 `id,type,iconId,name,...`，示例行证明宠物 ID、图标 ID、名称与属性数据由本地配置提供。列表/详情缺少自定义名时按 `id` 查 `pet.name`；详情图片使用服务端响应的 `icon` 直接定位 `p<icon>` 资源，而不是必然使用配置 `iconId`（`PetListUI.as:230-236`; `PetInfoUI.as:365-379`）。

详情材料图标还会查 `prop` 或 `pic` 配置（`PetInfoUI.as:282-284,431-445,571-578`）。应校验配置表存在对应行及 SWF 资源；不可用配置名/图标替代响应必需的 ID 而不验证。

## 最小可靠实现建议

1. 先实现只读命令 11：按当前账号/角色已持久化宠物集合稳定排序，采用请求 `p,n` 切片并返回 `pets` 数组；每行提供上述列表字段。空集合也返回 `pets: []` 和明确的容量/卡数数值，避免客户端对缺失数组取 `length` 崩溃。
2. 再实现只读命令 12：以 `index` 精确查同一角色的宠物；返回详情基础字段，保证 `icon` 对应客户端资源，`id` 对应本地配置。未知索引应返回项目已有协议错误格式，而非伪造默认宠物。
3. 首版可省略 `next_pet`、`pic` 和放生奖励字段，前提是客户端已有空值分支；`is_lockable/is_locked` 则应明确返回一致的布尔值。列表与详情应从同一持久化记录生成，避免列表可见但点开找不到。
4. 加测试覆盖空列表、单页、多页边界、容量空槽、已命名/默认名宠物、存在/缺失进化目标、未知 index，以及服务重启后数据一致。命令 40 扩容和命令 55/18/14/15 等写操作应另立协议与持久化测试，不混入只读首片。

推荐 JSON 响应字段类型为整数计数/等级/星级/属性、布尔锁状态、字符串或可解析 ID、数组 `pets`/`need_goods`。AS3 通过动态对象读取且常隐式转换，以上是兼容性建议，不是已证实的旧服务端类型约束。

## 未知项

- `pet_num` 是拥有数量还是其他统计值；容量恰满时的 `_maxpage` 公式行为。
- `index` 是否全局唯一、是否为槽位号，以及列表排序规则。
- `battle_state` 枚举值、`icon` 与 `id` 的权威映射及 `pro` 的业务含义。
- `next_pet` 的来源/资格规则、奖励字段的完整组合、锁定与放生/进化的持久化及资源扣减规则。
- 客户端命令 11/12 的静态读取不证明全部字段必填，也没有已知旧服务器抓包用于验证。
