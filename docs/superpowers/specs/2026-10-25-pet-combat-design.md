## 一、目标与边界

### 1.1 现状：三个已经确认的口径裂缝

这三条不是推测，是代码与客户端反编译交叉核对后的结论。

| # | 裂缝 | 证据 | 后果 |
|---|---|---|---|
| 1 | **面板显示成长值（`gw_*`），战斗完全不用它** | 【包】`PetAllInfoUI.as:158-163` 打印 `hp + getAdd(hp_tp) + "(" + hp_gw + ")"`；【码】`_combat_stats`（`app.py:3005`）只读 `_pet_base_stats` + `pro_*`，**从不读 `gw_*`** | 洗练 19 号（reroll `grows`）只改面板数字，战力不变 |
| 2 | **强化值在面板是"全量相加"，在战斗里 hp/def 只算一半** | 【码】`_combat_stats`：`+ pro_hp // 2`、`+ pro_phy_def // 2`，但 `+ pro_phy_att` 全量；面板 `getAdd(*_tp)` 全量 | 面板 100 强化 = 战斗 50，与 T04 定下的"面板=战斗"原则冲突 |
| 3 | **怪物完全不用 `monster.txt` 的六维** | 【码】`_monster_stats(level)`（`app.py:3040`）用合成曲线 `hp=60+1.8*(lv-1)`、`att=16+0.6*(lv-1)`；而【表】`monster.txt` 每行都有 `hp/phyAtt/phyDef/magAtt/magDef/speed`（1086 行，`hp` 中位数 130） | 怪物与宠物两套口径：怪物成长 ~31×（lv1→1000），宠物成长 ~7×（`1+0.006*(lv-1)`），等级越高越对不上 |

第 4 个更根本：**技能与特性一条都没进战斗**。【码】`_battle_side` 只发 `hp/att/def/speed`，
`_battle_record_simulated` 每回合发固定 `skill={"id":101,"pro":1,"dm":swing}`；宠物身上的
`skills`（`pet.txt` 每只 2~4 条）与 `buffs`（特性，1~7 条）只出现在 13 号面板里。

### 1.2 本阶段目标（可验收的四句）

1. **一个函数定口径**：新增 `_pet_stats(pet_row)` 成为宠物六维的唯一来源，12/13 面板、6/24/74/103 战斗、
   42/44 选宠、506 对手展示全部走它，做到"面板一个数、打起来也是这个数"。
2. **技能/特性真正参与回合**：主动技能决定伤害类型与倍率，特性决定命中/暴击/格挡/反伤/再生/控制，
   并且全部通过客户端**已识别**的回放字段表达（§4.5），不改 SWF。
3. **擂台改成异步镜像**：不再打 `monster.txt` 的怪，而是打"评分相近的队伍快照"，
   排名由真实评分排序，收益有上限（§6.6）。
4. **每阶段可独立回滚**：所有新数值走常量/开关，回滚只需改常量或关一个环境变量（§8）。

### 1.3 明确不做

| 不做 | 原因 |
|---|---|
| 元素相克矩阵（火克草…） | 随包配置表**没有**克制表；`skill.txt` 只有 `pro`（属性）列与 抗性/专精/克星 三族特性，没有"火→草 ×1.5"这类数据 →【未取证】，不在本规格发明 |
| 原服战斗公式还原 | 原服公式无抓包、无表、无端内计算（客户端**不做任何战斗数学**，只播服务器给的数字，见 §4.5） |
| 装备带技能参与回合 | `equip.txt` 的 `skills` 列是真实数据，但阶段 2 只做到"显示"；本规格只让它作为**猎人技能**参与 §4.9 的选技，效果与宠物共用一套 |
| 后台/定时任务（赛季结算、每日衰减） | 离线服没有 scheduler；一律"读时惰性结算"（沿用 `explore_ap` 按读补满的做法） |

## 三、宠物战斗数值公式

### 3.1 总公式（乘区 / 加区）

```text
# 单条属性 s ∈ {hp, speed, phyAtt, magAtt, phyDef, magDef}
lvf(s)      = 1 + 0.006 * (lv - 1)                       # 等级乘区
gwf(s)      = 1 + (gw_s / 1000) * (lv / 100)             # 成长资质乘区
prof(s)     = 1 + pro_s / 1000                           # 强化乘区（0..1000 → ×1.00..×2.00）
naturef(s)  = aValue/100  若 s == aKey
            = bValue/100  若 s == bKey
            = 1.0         否则
buff_flat(s)= Σ 限时增益的绝对加点（幸运四叶草 10026 等）

pet_stat(s) = round( base_s × lvf × gwf × prof × naturef ) + buff_flat(s)
```

| 区 | 类型 | 数据来源 | 量级 | 理由 |
|---|---|---|---|---|
| `base_s` | 加区（最内） | 【表】`pet.txt` 六维 | 3★ 302 合计 → 12★ 2400 合计 | 星级差异已经编码在 base 里（§3.5），不要再乘一次 |
| `lvf` | 乘区 | 【码】沿用 `0.006`（`app.py:3018`） | lv1 1.000 → lv1000 **6.994** | **必须与人物同系数**（T04 的 `_hero_stat_multiplier`），否则同场战斗一边线性一边指数 |
| `gwf` | 乘区 | 【表】`grows` 区间 × `pets.gw_*` | 3★ `gw≈15`→lv1000 ×1.15；12★ `gw≈80`→×1.80 | 让"成长"成为长线资质轴：同样 base，资质高者练到高级更强；洗练 19 号才有意义 |
| `prof` | 乘区 | 【表】`prop.txt 10505` remark 隐含上限 ~1000；【码】`LOCAL_PRO_CAP=1000` | 0→×1.00、500→×1.50、1000→×2.00 | 换成乘区是为了"不许无限强"：无论 base 多低，强化最多翻倍（对比：加区下 3★ 火龙 hp 39 + 1000 = 26 倍） |
| `naturef` | 乘区 | 【表】`nature.txt` | 1.2 / 0.8 | 表里就是百分比，直接用 |
| `buff_flat` | 加区（最外） | 【码】`_player_buffs`（`:1886`） | +18（四叶草） | 临时增益是对"当前总能力"的固定加点，放最外以免被乘区放大 |

**为什么乘区顺序是 lvf × gwf × prof × naturef**：乘法可交换，顺序只影响取整误差；
写成这个顺序是因为它对应"等级 → 资质 → 投入 → 天性"的叙事顺序，便于逐个开关调试（§8 的回退靠置系数为 1）。

**向后兼容**：lv1、`gw=0`、`pro=0`、`nature=0` 时 `pet_stat = base`，与今天的 `_pet_base_stats` **完全一致**
（火龙 39/65/52/60/43/50）。所以老存档在阶段 3 第一天不会变强也不会变弱。

### 3.10 伤害公式与 TTK

```text
dmg = max(1, round(K × att² / (att + defence) × element_match × crit × variance))

K        = 0.40        # 由 TTK 反推，见下表
att      = 物攻 若 damageType==1；魔攻 若 damageType==2
defence  = 物防 若 damageType==1；魔防 若 damageType==2
crit     = 1.5 若本次暴击，否则 1.0     # 1.5 来自客户端：FightProcess.as:765-768 把暴击飘字放大 1.5
variance = 0.92..1.08 的均匀随机（可选，默认开）
```

**K 的推导**（可复算）：

```text
击数 = hp_def × (att + def_def) / (K × att²)
对称单位（hp = att、def_def = att）→ 击数 = 2 / K
```

| K | 对称击数 = 2/K | 火龙(52) 打波利(def 52, hp 39) |
|---|---|---|
| 0.60（现值） | 3.33 | **2.3 击**（太快，见不到技能轮次） |
| **0.40（本规格）** | **5.00** | **3.9 击** |
| 0.30 | 6.67 | 5.2 击（超过下方回合预算） |

- 取 `K=0.40`：普通同族对打 3.5~4 击，正好落回 `LOCAL_SWINGS_PER_MONSTER=4`（`:3133`）这个已有的预算口径。
- 现状 K=0.6 的问题不是"太疼"，而是**战斗在技能触发之前就结束**：3★ 火龙 lv1 只挨 2.3 击，
  特性（暴击 7%、回避 10%）根本没有第二次触发机会。
- 回合预算（沿用并放大【码】`:3134/:3136`）：`LOCAL_BATTLE_ROUND_LIMIT` 12→**20**、
  `LOCAL_BATTLE_STEP_LIMIT` 30→**60**。理由见 §6.5：镜像 PvP 双方 3 单位、每单位 5 击，需要 ~8 回合；
  30 步会在第 4 回合被截断，表现成"打不完=输"。

```text
D = 内容难度系数（【本地】唯一的手调旋钮）
```

### 4.4 回合内触发顺序（时序表）

```text
R0  战前（每个单位只结算一次）
    1. 六维 = §3.1 公式
    2. 天赋/加成（51~56）→ 写回六维
    3. 抗性/专精/克星（11/12/13）→ 记入 element_match
    4. 守护/护盾（23/25）→ 初始盾值
    5. 速度排序：speed 降序，同速按 code 升序（猎人 code=0 先手）

R1..R20  每回合
    对每个存活单位，按 R0.5 的顺序：
    6. 若眩晕（冲锋/病毒类控制）→ 跳过，消耗一层
    7. 选目标：敌方存活单位中 hp 最低者（focus fire）
    8. 选技能：§4.9
    9. 命中判定：p_avoid 与 p_hit 抵消；未命中 → dm=0（客户端显示 MISS）
    10. 伤害结算：K × att²/(att+def) × element_match
    11. 暴击判定 → ×1.5（与客户端飘字放大倍率一致）
    12. 减伤链：吸收(7) → 护盾(25/23) → 破甲/心眼修正
    13. 命中生效后：吸血(8)、致命(9)、溅射(10)
    14. 受击反制：反弹(6)、幸运(22)、复活(24)
    15. 目标死亡 → 本次不反击
    16. 反击：目标若存活，用它的普通攻击回敬（不带技能）
    回合末：
    17. 再生(1)、DOT(17)、嗜血(15) 层数、嗜血/腐蚀 的临时增减回滚
    18. 任一方全灭 → 结束；否则进入下一回合
    19. 回合数 > 20 或步数 > 60 → 结束，判定为"未胜"（沿用 `_record_is_win` 的语义）
```

**胜负判定不变**：【码】`_record_is_win`（`:3238`）看最后一步是否 `def.is_dead=True`，
所以引擎必须保证"胜利的最后一个动作一定是打死守方"。这条已有单测覆盖，阶段 3 不能改语义。

```text
generation' = max(gen_m, gen_v) + (1 if gen_v <= gen_m else 0)
```

### 6.2 目标：异步镜像（离线服的 PvP 等价物）

```text
一次擂台 = 我方当前出战队伍  vs  一张"对手快照"（同账号历史 / 本地生成）
快照里存的是完整战斗输入（六维 + 技能 + 特性 + 等级 + 星级 + 世代），不是引用当前 pets 行
```

- 为什么不是"实时同步 PvP"：这是单人离线服，没有第二个客户端。
- 为什么不是"打自己的当前队伍"（真镜像）：那样 100% 是"自己打自己"，胜负只由随机数决定，
  评分的意义就是噪声。**快照 + 评分窗口**才能让"变强 → 打赢更强的对手 → 评分上升"成立。
- 【未取证】原服是否有 PvP 排行、赛季、匹配算法 —— 客户端只有 `RingUI`/`RingResultUI`/`RingTopUI` 三个界面
  （SWF 里**没有** `ArenaUI` 这个类，见附录 A），说明擂台就是"选对手 → 打 → 结算 → 看榜"四步。

### 6.4 匹配与战力

```text
power(队伍) = Σ_单位 [ hp×0.25 + (phy_att + mag_att)×1.00 + (phy_def + mag_def)×0.60 + speed×0.50 ]
            + Σ_技能 [ 0.5 × skill.damage ]
            + Σ_特性 [ 3 × skill.level ]
```

| 单位 | 样例战力 | 说明 |
|---|---|---|
| 3★ 火龙 lv1（无投入） | 210 | §3.9 第 1 行 |
| 3★ 火龙 lv50 pro100 | 302 | 早期 |
| 5★ 小火猴 lv100 pro200 | 448 | 中期 |
| 12★ 龙神 lv1000 pro1000 | 27344 | 天花板（用来确认权重不爆） |

- **匹配窗口**：`|power(对手) - power(我方)| / max(...) ≤ 0.20`，按 rating 最接近优先；
  窗口内没有对手 → 用"我方 power × (0.90..1.10)"现场生成一支真实物种的队伍（LOCAL）。
- 【本地】权重的作用只是**排序**，不参与伤害；所以权重调错只影响匹配，不影响单场手感。

### 6.5 排名与评分

```text
胜：rating += 16 × (1 - 1/(1 + 10^((r_opp - r_me)/400)))     # 标准 Elo，K=16
负：rating -= 16 × (1/(1 + 10^((r_me - r_opp)/400)))
新账号 rating = 1000；上下限 0..3000

排名 = rating 降序（同分按 last_win_at 早者优先）
507  = 第 1 页 9 行：自己那一行 + rating 相邻的 8 条（快照对手）
week reset：按 ISO 周重置到 1000 + 保留"历史最高"用于展示（不参与匹配）
```

- **反无限强（明确要求）**：
  1. **同对手每日只计分一次**（`arena_record` 去重）→ 不能刷同一支弱队。
  2. **7 天不打，rating 每天 −2%**（惰性结算，读 507 时算）→ 不能"躺冠"。
  3. **rating 上限 3000**，且奖励按 rating 分段而不是按胜负线性放大。
  4. **战力窗口 20%**：不满足窗口的对手不给分（打赢弱队 +0）。
  5. **每赛季（ISO 周）重置 rating 但不重置宠物** → 强度靠养成，排名靠当周活跃。

### 6.6 平衡目标（可量化验收）

| 指标 | 目标 | 验证方式 |
|---|---|---|
| 镜像对局长度 | 6~10 回合（`LOCAL_BATTLE_ROUND_LIMIT=20` 够用） | 模拟器跑 200 场统计回合数分布 |
| 同战力胜率 | 40%~60% | 模拟器：同 power 不同物种组合对打 |
| 越级惩罚 | 战力差 20% → 胜率 ≤ 25% | 模拟器 |
