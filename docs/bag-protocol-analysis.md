### 空背包可行性

```text

```

## 持久化与实现建议

当前 `server/pet_hunter_server/app.py:70-105` 的建表逻辑只有账号、玩家和账号关联，没有背包/装备表。空背包可作为明确的“尚无物品”的本地初始状态；一旦发放、购买、捕获奖励或制作加入物品，必须先建立持久库存，不能继续返回常量空列表。

建议库存记录至少保存玩家外键、稳定实例 index、配置 id、team/分类、数量；装备实例另存品质/强化/属性以及穿戴位置。容量也应持久化或来自明示的版本化默认策略。所有读取先验证玩家存在与实例归属；分页按稳定顺序，限制 p/n，分类仅接受已恢复范围。新增表采用非破坏迁移，保留 `server/instance/game.sqlite3`。

最小实施顺序：验证玩家的 22 空列表 → 真机逐个打开道具/材料/装备 → 持久化库存与合法配置映射 → 39 真实实例详情 → 最后恢复使用、穿戴、出售等事务。未知实例返回既有明确错误协议，不构造假装备；未知动作继续明确未实现。

验证重点：三分类、无效玩家、分页边界、重启保留物品、跨玩家实例不可读、出售的物品删除与余额增加必须在同一事务内且重复提交不会重复得款。以上建议不代表本轮已经实现这些功能。
